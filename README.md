# RF Concepts in Smart Cities

**A gallery of interactive Three.js micro-demos exploring private 5G, outdoor small cells, and edge AI in urban environments.**

Six self-contained visualizations turn core RF-engineering and edge-computing concepts into real-time, manipulable 3D scenes — beamforming lobes steering through a downtown block, sensor telemetry streaming to edge nodes, coverage blooming through an urban fabric as a network densifies.

Built with **Next.js 15**, **TypeScript**, **React Three Fiber**, **Tailwind CSS + shadcn/ui**, and **Framer Motion**. Everything is procedural — the project runs instantly with zero external data dependencies.

```bash
npm install
npm run dev        # http://localhost:3000
```

```bash
npm run build
npm run start
```

## Deploying to Render

The repo ships with a [`render.yaml`](./render.yaml) blueprint:

1. Push the repo to GitHub.
2. In the [Render dashboard](https://dashboard.render.com/blueprints), choose **New → Blueprint** and connect the repo.
3. Render provisions a Node web service (`npm ci && npm run build` → `npm run start`) automatically.

## The six demos

| # | Demo | Concept |
|---|------|---------|
| 01 | **Urban Beamforming Lobes** | A pole-mounted small-cell array in a procedural downtown. Adjust element count, steering angle, spacing, and Tx power; the glowing lobe surface is a real uniform-linear-array factor (log-scaled dB). Drop user terminals on the street and watch their link budgets react to steering and building blockage. |
| 02 | **Sensor-to-Edge Data Flow** | City sensors stream telemetry to edge nodes co-located with small cells. Particle speed and colour encode one-way latency (propagation + switching + load-dependent queueing). Crank workload intensity and watch streams congest. |
| 03 | **Volumetric Coverage Growth** | Small-cell densification as an animated street-level heat field that respects building occlusion. Trigger rollout steps, scrub the deployment timeline, or click to place cells and hunt coverage holes yourself. |
| 04 | **Interference Noise Field** | Building density becomes a living noise haze — the interference floor rises exactly where the city is densest. Place cells and compare how much clean "dominance area" the same hardware wins in a plaza vs. the dense core. |
| 05 | **Antenna Pattern on a Pole** | A datasheet-style 3D radiation pattern on a streetlight small cell inside an urban canyon. Rotate azimuth, adjust downtilt and beamwidths, toggle dB vs. linear scaling, and watch the footprint wash across street and façades. |
| 06 | **Edge Workload Placement** | An edge-orchestration puzzle: assign AI workloads (traffic inference, video analytics, sensor fusion) to capacity-limited edge nodes. Live scoring balances latency against overload — greedy auto-place included for comparison. |

Every demo has orbit controls, a collapsible control panel, an engineering explanation sidebar, **Reset Scene**, and **Take Screenshot**.

## The models (and their limits)

The math is simplified but physically plausible — real formulas, honest caveats:

- **Free-space path loss** — `FSPL(dB) = 20·log₁₀(d) + 20·log₁₀(f) + 32.44`, with a fixed per-obstruction penetration penalty (~18 dB) when buildings block line-of-sight (segment vs. AABB tests).
- **Array patterns** — normalized uniform-linear-array factor `|sin(Nψ/2)/(N·sin(ψ/2))|` with electronic steering, plus the classic `50.8/(N·d/λ)` half-power-beamwidth approximation; panel patterns in Demo 05 use Gaussian main lobes with a controlled back lobe.
- **Latency** — fibre-speed propagation + per-hop switching + a queueing term that grows super-linearly with load.
- **Urban clutter** — local built-mass density as a proxy for scattering/interference (Demo 04) and shadowing.

These are visualization-grade models: right shape, right trends, right units — not a replacement for ray-tracing propagation tools.

## Public-data principles

All geometry — buildings, street grid, parks — is generated by a deterministic, seeded procedural district model (`generateCityScape()` in [`lib/three-utils.ts`](./lib/three-utils.ts)) so the gallery runs with no external data. Window façades are stamped in world space by a small shader extension, so any footprint source gets believable architecture for free. The interface is deliberately data-shaped:

```ts
interface Building { x: number; z: number; width: number; depth: number; height: number }
```

Anything that produces `Building[]` — OpenStreetMap extracts, municipal open-data footprints, LiDAR-derived massing — can replace the procedural generator without touching a single demo. A typical swap: fetch OSM building polygons for a district, compute oriented bounding boxes, scale heights from `building:levels`, and feed the array in.

## Performance notes

- Cities render as a single `InstancedMesh` draw call; particle systems share one `THREE.Points` per demo.
- Heat fields/dominance maps are `DataTexture`s recomputed only when inputs change, never per frame.
- Post-processing is a shared mipmap-bloom + vignette stack with a high luminance threshold, tuned so only genuinely emissive signal elements glow in the day-lit scenes.
- Demos are code-split and load only when opened.
